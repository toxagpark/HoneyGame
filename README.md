# 🍯 HoneyGame

Telegram-игра про медведей, мёд и дуэли. Бот на Go: регистрируешься — получаешь мёд, вызываешь соперника на бой за ставку, шансы 50/50.

## Как играть

Игра живёт в одном игровом чате: бот добавляется в общий чат с друзьями, все ответы — туда.

| Команда | Что делает |
|---------|-----------|
| `/start` | Регистрация. Новый игрок получает **15 мёда** 🍯; повторный вызов обновляет имя (и чинит потерянную строку баланса) |
| `/me` | Твой профиль: внутренний ID, имя, баланс мёда |
| `/getUser` | Профиль (старое имя команды, работает как `/me`) |
| `/fight <ставка>` | Создать открытый вызов на N мёда. Ставка сразу списывается и «висит в бою» |
| `/fights` | Список открытых вызовов других игроков (свои не показываются) + кнопки «взять» |
| `/top` | Топ игроков по мёду: имя — мёд, от большего к меньшему |
| Кнопка **🗡 Взять вызов** | Принять чужой вызов: у тебя списывается ставка, идёт анимация боя, победитель забирает банк (2× ставки) |
| Кнопка **✖️ Отозвать** | Отозвать свой вызов — ставка возвращается |

Игроки и их мёд определяются по Telegram-ID автора команды (`From.ID`), а все ответы бот пишет в игровой чат из `TG_CHAT_ID`.

Примеры боёв пишутся в журнал `challenges`, активные вызовы живут в `active_challenges`.

## Настройка

Переменные окружения (`.env`):

- `TELEGRAM_BOT_TOKEN` — токен бота;
- `TG_CHAT_ID` — ID игрового чата, куда бот шлёт все ответы (добавь бота в общий чат с друзьями и возьми его ID; отрицательное число для групп/супергрупп);
- `POSTGRES_*` — подключение к базе (см. `internal/core/postgres`).

## Технологии

- **Go** + [telego v1.12](https://github.com/mymmrac/telego) — Telegram Bot API (long polling, роутер `telegohandler`, inline-клавиатуры)
- **PostgreSQL** — схема `honey`, миграции через `golang-migrate`
- **pgx v5** — драйвер и пул соединений
- **Docker Compose** — база в контейнере, наружу прокинута через socat-проброс порта

## Архитектура

Классические слои, файл = одна операция:

```
cmd/honey/              # точка входа: бот, роуты команд и callback-кнопок
internal/
  core/
    domain/             # сущности (User, ActiveChallenge) и доменные ошибки
    postgres/           # пул соединений, конфиг из .env
    transport/tg/       # конфиг бота (TG_CHAT_ID) и Telegram-хелперы (send/reply/edit/callback)
  feature/
    users/
      repository/postgres/   # SQL: create/get/get_by_id/update/top
      service/               # бизнес-правила регистрации, профилей, топа
      transport/tg/          # хендлеры /start, /me, /getUser, /top
    fight/
      repository/postgres/   # SQL: вызовы, отзыв, бой транзакцией
      service/               # валидации, владение вызовом, исход боя
      transport/tg/          # хендлеры /fight, /fights, inline-кнопки, анимация
migrations/             # NNNNNN_name.{up,down}.sql
docs/                   # схема БД (database_schema.md)
```

Правила слоёв:
- **transport** — парсинг Telegram-апдейтов, отрисовка сообщений, тексты. Никакой бизнес-логики;
- **service** — резолв игрока по `tg_user_id`, проверки владения, ставки. Возвращает доменные ошибки;
- **repository** — только SQL. Маппит ошибки БД в доменные (`pgx.ErrNoRows` → `ErrUserNotFound`, код `23505` → `ErrChallengeAlreadyExists`).

## Как устроены деньги (мёд)

Экономика держится на атомарности, а не на честности игроков:

- **Создание вызова** — транзакция: `SELECT ... FOR UPDATE` баланса → проверка → списание → вставка вызова. Либо и вызов, и списание, либо ничего.
- **Бой** — одна транзакция: удаление вызова из `active_challenges` под блокировкой строки (двое нажавших одновременно — бой возьмёт один), блокировка балансов обоих участников **в одном порядке по `user_id`** (защита от дедлоков), проверка ставки у принявшего, 50/50, `+2× ставки` победителю, запись в журнал, commit. Любая ошибка до commit — откат, мёд цел.
- **Отзыв** — транзакция: удалить вызов + вернуть ставку.
- **Один активный вызов на игрока** — не код, а `UNIQUE (creator_user_id)`: два одновременных `/fight` — второй получит ошибку от базы.

Про параллельные бои: медведь может участвовать в нескольких боях одновременно, если на них хватает мёда — это фича, а не баг. База гарантирует, что сумма балансов не изменится и в минус никто не уйдёт.

Подробности схемы БД — в [`docs/database_schema.md`](docs/database_schema.md).
